INSTALLATION & UPDATE

Kein SSH-Vorwissen nötig. Der einfachste Weg braucht eine einzige Datei und einen Klick im MiSTer-Menüe – das Frontend selbst muss man gar nicht herunterladen.
WELCHER WEG PASST ZU DIR?
A
AM EINFACHSTEN
Eine kleine Datei auf die Karte, im OSD einmal antippen. Den Rest macht das Skript allein – herunterladen, einrichten, starten.
B
PER SSH
Schon eine Sitzung offen? Ein Befehl erledigt genau dasselbe wie Weg A.
C
OHNE INTERNET
Der MiSTer hat kein Netz, oder es soll eine bestimmte Fassung sein: komplettes Paket kopieren, vor Ort installieren.
VORAUSSETZUNGEN
MiSTer FPGA mit aktueller Firmware – Python 3 ist dort immer schon dabei
Eine Möglichkeit, eine Datei auf die Karte zu bekommen: WinSCP, ein anderer SFTP-Client, oder einfach die SD-Karte im PC
Für Weg A und B: Internetzugang am MiSTer (im Heimnetz meist automatisch da)
Für Musik (freiwillig): mpg123 – gehört zur MiSTer-Firmware dazu
Nichts wird am System verändert. Das Frontend ist ein Python-Programm, das auf einem völlig unveränderten MiSTer läuft – kein anderer Kernel, kein Linux-Abbild, keine zusätzliche Hardware. Frontend_Uninstall.sh macht alles wieder rückgängig.

INSTALLATION – WEG A

Am einfachsten, kein SSH nötig. Du brauchst nur Frontend_Install.sh – nicht das ganze Paket.
1
Datei herunterladen
Scripts/Frontend_Install.sh von GitHub speichern (Rechtsklick → Speichern unter).
2
Auf den MiSTer kopieren
Die Datei nach /media/fat/Scripts/ legen – per WinSCP, oder die SD-Karte kurz in den PC stecken.
3
Im MiSTer-OSD ausführen
Hauptmenüe → Scripts → „Frontend Install“ antippen. Einmal, mehr nicht.
4
Fertig
Das Skript lädt alles Weitere selbst, richtet den Autostart ein und startet das Frontend am Ende von allein. Ein Neustart von Hand ist nicht mehr nötig.
Dasselbe Skript ist auch der Update-Weg: einfach noch einmal ausführen. Eigene Musik, Boxart und Einstellungen bleiben dabei unangetastet, nur die Programmdateien werden ersetzt.
ALTERNATIVEN
B – per SSH, ein Befehl:
curl -Ls https://raw.githubusercontent.com/dragrem2k-coder/mister-frontend/main/Scripts/Frontend_Install_Remote.sh | bash
C – ohne Internet, aus dem kopierten Paketordner:
cd /media/fat/MiSTer_Frontend
./Scripts/Frontend_Install_Offline.sh --yes
Seit Build 140 ist egal, von wo aus du den Offline-Installer startest – aus dem Paketordner, aus dessen Scripts/, oder als Kopie in /media/fat/Scripts/ für das OSD.

NACH DER INSTALLATION

Das Frontend läuft sofort. Schön wird es mit Covern – und die gibt es auf zwei Wegen.
1. SELBST HERUNTERLADEN
Im Frontend: System → Wartung → „Boxart herunterladen“. Läuft direkt auf dem MiSTer, kein PC nötig. Wer sowohl Röhre als auch HDMI nutzt, lässt beide Grössen laden – das Frontend wählt dann automatisch die passende.
2. ÜBER UPDATE ALL – WER MAG
Update All kann die MiSTer Game Artwork Database mitinstallieren. Sie landet unter /media/fat/docs/<System>/Artwork/, und das Frontend liest sie von sich aus – nichts kopieren, nichts umbenennen. Bei einem Nutzer lagen dort 21.198 Cover, ungenutzt.
Aus denselben Ordnern kommen auch Jahr, Genre, Entwickler, Spieleranzahl und die Spielbeschreibungen, die in der Galerie neben dem Cover stehen.
Kein Muss. Beide Wege führen zum selben Ergebnis, und sie vertragen sich: eigenes Artwork hat immer Vorrang, die Datenbank füllt nur Lücken. Abschalten lässt sie sich unter System → Anzeige & Sound → „Fremdes Artwork/Daten“.
MINIATUREN VORBEREITEN – WOFÜR IST DAS?
Cover liegen gross auf der Karte, oft 900×1200 Bildpunkte. Auf den Bildschirm kommen sie in drei viel kleineren Kästen – für Liste, Galerie und Raster. Jedes Cover muss also beim ersten Anschauen verkleinert werden, und das dauert je Spiel ein bis zwei Sekunden. Genau das ist das kurze Stocken, das man beim ersten Durchblättern einer neuen Sammlung merkt.
System → Wartung → „Miniaturen vorbereiten“ erledigt das im Voraus und legt das Ergebnis auf der Karte ab. Danach ist jedes Cover sofort da, auch nach einem Neustart.
Bei grossen Sammlungen läuft das eine Weile – Abbrechen und später Fortsetzen geht jederzeit, Berechnetes bleibt erhalten. Röhre und HDMI haben getrennte Zwischenspeicher. Nötig ist es nicht: ohne den Lauf funktioniert alles genauso, nur eben mit dem kurzen Moment beim ersten Hinsehen.

UPDATE & HILFE

Das Frontend schaut im Leerlauf selbständig nach, ob es eine neuere Fassung gibt, und sagt Bescheid.
SO AKTUALISIERST DU
1
Denselben Weg noch einmal gehen
Egal ob A, B oder C – einfach erneut ausführen. Bei Weg A also: im OSD Scripts → „Frontend Install“.
2
Fertig
Die Programmdateien werden ersetzt und vorher gesichert. Eigene Musik, Boxart, Metadaten, selbst ersetzte System-Logos und alle Einstellungen bleiben unangetastet.
Dateien von Hand per WinSCP ersetzt? Dann danach einmal:
/media/fat/Scripts/Frontend_Update.sh
SCHNELLE FEHLERBEHEBUNG
Frontend reagiert nicht
kill $(cat /tmp/frontend.lock)
Notaus (Autostart-Problem)
touch /media/fat/frontend/disable
Diagnose-Log ansehen
tail -50 /tmp/frontend.log
Wieder entfernen
./Scripts/Frontend_Uninstall.sh
Das Deinstallieren fragt nach, ob eigene Boxart, Musik und Einstellungen erhalten bleiben sollen. Danach ist der MiSTer genau so, wie er vorher war.
