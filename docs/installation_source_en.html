github.com/dragrem2k-coder/mister-frontend MiSTer Custom Frontend

INSTALLATION & UPDATE

No SSH knowledge needed. The easiest route takes a single file and one click in the MiSTer menu – you never download the frontend itself.
WHICH ROUTE SUITS YOU?
A
EASIEST
One small file onto the card, one tap in the OSD. The script does the rest by itself – download, set up, launch.
B
OVER SSH
Already have a session open? One command does exactly what route A does.
C
NO INTERNET
The MiSTer has no network, or you want a specific version: copy the whole package, install it locally.
REQUIREMENTS
A MiSTer FPGA with current firmware – Python 3 is always part of it
Some way to get a file onto the card: WinSCP, another SFTP client, or just the SD card in your PC
For routes A and B: internet access on the MiSTer (usually already there on a home network)
For music (optional): mpg123 – part of the MiSTer firmware already
Nothing in the system is changed. The frontend is a Python program running on a completely untouched MiSTer – no different kernel, no Linux image, no extra hardware. Frontend_Uninstall.sh undoes all of it.
2/4  -  INSTALLATION
github.com/dragrem2k-coder/mister-frontend MiSTer Custom Frontend

INSTALLATION – ROUTE A

The easiest way, no SSH needed. All you need is Frontend_Install.sh – not the whole package.
1
Download the file
Scripts/Frontend_Install.sh from GitHub (right-click → Save link as).
2
Copy it to the MiSTer
Put the file into /media/fat/Scripts/ – over WinSCP, or with the SD card briefly in your PC.
3
Run it in the MiSTer OSD
Main menu → Scripts → “Frontend Install” – once, that is all.
4
Done
The script fetches everything else itself, sets up autostart and launches the frontend when it is finished. No manual reboot needed.
The same script is also the update route: just run it again. Your own music, cover art and settings are left untouched; only the program files are replaced.
ALTERNATIVES
B – over SSH, one command:
curl -Ls https://raw.githubusercontent.com/dragrem2k-coder/mister-frontend/main/Scripts/Frontend_Install_Remote.sh | bash
C – without internet, from the copied package folder:
cd /media/fat/MiSTer_Frontend
./Scripts/Frontend_Install_Offline.sh --yes
Since build 140 it does not matter where you start the offline installer from – the package folder, its Scripts/, or a copy in /media/fat/Scripts/ for the OSD.
3/4  -  COVER ART
github.com/dragrem2k-coder/mister-frontend MiSTer Custom Frontend

AFTER INSTALLING

The frontend runs right away. It gets good-looking with cover art – and there are two ways to get it.
1. DOWNLOAD IT YOURSELF
In the frontend: System → Maintenance → “Download box art”. Runs on the MiSTer itself, no PC needed. If you use both a CRT and HDMI, fetch both sizes – the frontend picks the right one automatically.
2. VIA UPDATE ALL – IF YOU LIKE
Update All can install the MiSTer Game Artwork Database alongside it. It ends up under /media/fat/docs/<System>/Artwork/, and the frontend reads it by itself – nothing to copy, nothing to rename. One user had 21,198 covers sitting there, unused.
The same folders also supply year, genre, developer, player count and the game descriptions shown next to the cover in gallery view.
Not required. Both routes lead to the same result, and they get along: your own artwork always wins, the database only fills gaps. You can switch it off under System → Display & Sound → “External artwork/data”.
PREPARING THUMBNAILS – WHAT FOR?
Cover art sits on the card at full size, often 900×1200 pixels. It reaches the screen in three much smaller boxes – for list, gallery and grid. So every cover has to be scaled down the first time you look at it, and that takes one or two seconds per game. That is exactly the little stutter you notice when first paging through a new collection.
System → Maintenance → “Prepare thumbnails” does it in advance and stores the result on the card. After that every cover is there instantly, even after a reboot.
With a large collection this runs for a while – you can stop and continue later at any time, and what is done stays done. CRT and HDMI keep separate caches. It is not required: without it everything works just the same, only with that short moment the first time you look.

UPDATE & HELP

While idle the frontend checks by itself whether a newer version exists, and tells you.
HOW TO UPDATE
1
Take the same route again
A, B or C – just run it again. For route A that means, in the OSD: Scripts → “Frontend Install”.
2
Done
The program files are backed up and then replaced. Your own music, cover art, metadata, any system logos you swapped in and all settings are left untouched.
Replaced files by hand over WinSCP? Then run this once afterwards:
/media/fat/Scripts/Frontend_Update.sh
QUICK TROUBLESHOOTING
Frontend not responding
kill $(cat /tmp/frontend.lock)
Emergency stop (autostart trouble)
touch /media/fat/frontend/disable
Look at the diagnostic log
tail -50 /tmp/frontend.log
Remove it again
./Scripts/Frontend_Uninstall.sh
Das Deinstallieren fragt nach, ob eigene Boxart, Musik und Einstellungen erhalten bleiben sollen. Danach ist der MiSTer genau so, wie er vorher war.
